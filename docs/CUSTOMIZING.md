# Customizing the card

The card template and CSS are generated by `scripts/07_build_apkg.py`. Edit `QUESTION`, `ANSWER`, or `CSS` there, then rebuild:

```powershell
python scripts/07_build_apkg.py
python scripts/validate_deck.py
```

If you edit the note type directly in Anki, the next rebuild will overwrite those changes. Keep customizations in the build script.

## Front template

```html
<input type="checkbox" id="pinyin-toggle" class="pinyin-toggle">
<label for="pinyin-toggle" class="hanzi-wrap">
  <div class="pinyin hover-pinyin">{{Pinyin}}</div>
  <div lang="zh-Hans" class="hanzi">{{Hanzi}}</div>
</label>
```

The pinyin sits above the Hanzi with zero opacity but keeps its layout space. Desktop users hover the Hanzi; touch users tap it to toggle pinyin on or off. The hidden checkbox plus label gives a real tap toggle without JavaScript, so it works on AnkiDroid as well as desktop. Keeping the pinyin in normal flow means long sentences wrap inside the card instead of extending above the top edge and being clipped.

## Back template

```html
<div lang="zh-Hans" class="hanzi">{{Hanzi}}</div>
<div class="pinyin">{{Pinyin}}</div>
<hr>
<div class="english">{{English}}</div>
<div class="audio">{{Audio}}</div>
```

English and audio appear only on the back. The deck still uses one card and one `afmt`.

## Style notes

- **Hanzi** uses Kai/KaiTi at `clamp(30px, 6vw, 48px)`. The fixed `48px` declaration before the `clamp()` is a fallback for older webviews.
- **Pinyin** uses a Times New Roman-led serif stack. Palatino and Georgia are missing the pinyin caron vowels (`ǎ ǐ ǒ ǔ`) and ü-tone glyphs (`ǖ ǘ ǚ ǜ`); using them causes per-glyph fallback and inconsistent tone marks. Later fallbacks cover Linux and Android.
- **Hover pinyin** is in normal flow, not absolutely positioned. Removing the space reservation will reintroduce clipping on long sentences.
- **Touch behavior** is handled by `@media (hover: none)`, which disables the emulated sticky hover and leaves the checkbox as the only toggle.
- **Dark palette**: `rgb(47, 47, 49)` background, white text, `#55dd55` pinyin, `#ffd166` sandhi changes.

## Optional fields

These are not enabled in the default template. Insert the snippets into `QUESTION` or `ANSWER` in `scripts/07_build_apkg.py`; no data regeneration is needed.

Traditional Hanzi:

```html
<div lang="zh-Hant" class="hanzi traditional">{{HanziTraditional}}</div>
```

Surface-tone pinyin with changed syllables bold:

```html
<div class="pinyin sandhi">{{PinyinSandhi}}</div>
```

Zhuyin:

```html
<div class="zhuyin">{{Zhuyin}}</div>
<div class="zhuyin sandhi">{{ZhuyinSandhi}}</div>
```

Original sequence number:

```html
<div class="meta">#{{Sequence}}</div>
```

The existing styles cover these snippets. `PinyinSandhi` and `ZhuyinSandhi` use `<b class="tone-change">` around syllables whose surface tone differs from the lexical reading.

## Rebuilding only the package

Template-only changes do not require rerunning the pinyin or audit stages:

```powershell
python scripts/07_build_apkg.py
python scripts/validate_deck.py
```

`validate_deck.py` checks the template tokens and CSS in the built package. If you change the expected CSS, update the check in `scripts/validate_deck.py` as well.
